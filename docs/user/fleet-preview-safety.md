# Fleet planning and safe controller membership

`metactl fleet sync --preview` resolves each selected project's real configuration,
profile, sources, packs and targets. It compiles generated bytes in temporary
storage, then checks the proposed adoption mode against the project's actual
destinations and managed state. The temporary storage is removed on return.

Preview does not create or change files, symlinks, permissions, staging, lockfiles,
plans or logs in the controller or linked projects. Initial loading may populate
the bundled library in the user's global cache. This guarantee is specific to
**fleet preview**; ordinary `metactl sync --preview` still stages project outputs.

## Reading the result

Each successfully checked member has `status: planned`, with `plan.targets`:

- `planned_output_files`: complete destination paths relative to that member.
- `planned_skill_count`: number of generated `SKILL.md` entry points for a target.
- `apply_mode` and `actions`: the adoption mode and real destination observations.

These are expected outputs, not evidence that files have been installed.
`skill_visibility` still reports the currently installed files. Human output
shows planned file and skill counts separately for each target.

Invalid configuration, missing profiles/packs/targets and destination conflicts
mark a member `failed` and cause exit code 10. Later members are still checked.
Disabled or missing linked paths/configurations retain their existing skipped
status. `defaults.fleet_sync_adopt` selects patch or refuse behavior consistently
for preview and apply; preview no longer assumes every configured member can sync.

An explicit linked-project profile takes precedence over the invocation's
`--profile`. Otherwise the invocation profile applies to members. `--no-profile`
disables the machine default for members without an explicit selected profile.
Project profile inheritance and local configuration still use normal resolution.

## Locks and controller membership

`fleet sync --apply` holds the controller operation lock for the whole operation.
When a member resolves to that same canonical filesystem directory, its sync runs
in the controller process under the existing lock. Direct paths, symlinks and
parent-directory aliases use the same rule. Other members acquire their own locks
through the normal sync invocation. Existing external locks are never removed or
exempted based on process IDs or environment variables.

If writing the fleet log fails after members run, the command exits nonzero and
reports `log_error` while preserving each member's actual result, including
`applied`. Inspect those results before retrying; a failed log is not a rollback.

## Limits

Preview is an observation, not a reservation or apply authorization. It does not
fetch remote sources, test write permission by writing probes, or promise that
another process will leave files unchanged. Apply checks source freshness and
filesystem access again. Project writes remain serialized, and independent
member failures do not make fleet application transactional.
