# Registry helper boundaries

The registry owns library loading, policy selection, resolution, and compile
orchestration. Candidate discovery and instruction formatting have separate
internal modules so their rules can be understood without navigating that
orchestration.

- `library_discovery.rs` normalizes imported candidates and computes search
  evidence, ranking, and explanations. Candidate quarantine and provenance
  semantics remain unchanged.
- `library_instruction_format.rs` formats instruction references, enforces
  instruction-document byte budgets, constructs resource names, and reads
  declared skill-card metadata. It preserves existing formatting and error
  behavior.
- `library_registry.rs` retains resource IO and its cache, registry state, and
  orchestration. Helpers expose only the parent-module visibility needed by
  existing callers; no public API or dependency is added.

This extraction preserves function bodies. It does not change candidate trust,
search scores, generated bytes, truncation thresholds, filesystem behavior, or
error messages. Existing tests remain attached to the registry so they exercise
the same public operations after the move.

## Verification

Run `cargo test --offline -p metactl --lib library_registry`,
`cargo test --offline -p metactl --test cli_workflow compile_workflow`,
`cargo test --offline -p metactl --test cli_workflow search_workflow`, and
`cargo fmt --check`. Compare moved function bodies with the base revision.
Run the repository architecture gate with the companion CLI extraction; this
change alone does not repair the separate `main.rs` limit violation.

Regression coverage includes candidate quarantine, deterministic discovery,
duplicate manifests, ranking and match evidence, skill-card routing, target
suppression, generated frontmatter, resource-cache invalidation, and instruction
budget enforcement. Changes to any of those behaviors belong in a separate
behavior-changing review with focused regression tests.
